Data Dictionary / Clinical outcomes

CORE_Member_Pathway

Object Core (VayuHealth_Program_CORE) · CORE_Member_Pathway

Business definition

One row per (member_cin, ecm_enrollment_start_date): member_name and workflow_status from MART_Cumulative_Members (legacy membername / workflowstatus when the normalized column is blank; current enrollment fills a still-blank value), device flags, 60-day measurement flags, cgm_type, bgm_type, and a single pathway label. The first matching rule wins: (1) Active CGM + recent GMI = CGM Active; (2) Active CGM + no recent GMI = Possible CGM Malfunction; (3) No active CGM + recent GMI = Possible CGM Malfunction; (4) Active BGM + recent glucose = BGM Active; (5) Active BGM + no recent glucose = Possible BGM Malfunction; (6) No active BGM + recent glucose = Possible BGM Malfunction; (7) everything else enrolled = A1c; (8) not enrolled = blank on this CORE view. Monthly MERGE into MART_Cumulative_Members keeps the last non-blank pathway when Incoming is blank (discharge stick). No active device includes an inactive device and no device of that type. A recent measurement with no matching active device is a malfunction.

Terms used on this page

  • A1c: A blood test that shows a person's average blood sugar over about the last three months. Also written HbA1c. Higher numbers mean less controlled diabetes.
  • BGM: Blood glucose meter: a finger-stick device a member uses to check blood sugar. Sprite may call it SMBGS.
  • CGM: Continuous glucose monitor: a sensor worn on the body that measures blood sugar all day (for example Dexcom or Libre).
  • CORE: The BigQuery layer where SQL turns raw source data into business meaning (for example enrollment episodes). CORE objects are views.
  • GMI: Glucose Management Indicator: an estimate of A1c calculated from CGM readings.
  • MERGE: A database step that updates rows that already exist and adds rows that are new, without duplicating them.
