STG_Member_Activity_Log

Object Staging (VayuHealth_Program_STG) · STG_Member_Activity_Log

Business definition

Required for phases: member_cin, activity_date, description. Sprite Provider lands as accountable_provider. Monthly load keeps Vayu Health only (non-Vayu providers such as New Life Discovery Project, Inc. are dropped in Python). Feeds CORE_Member_Activity_Log → ECM / phase models.

touch_type is a structural alias (activity_type / service_type / type) when present. Sprite activity id is preserved for STG/CORE dedupe. Loader maps Sprite performer fields (activity_performed_by → specialist, activity_performed_by_provider → accountable_provider, activity_performed_by_team → care_coordinator_team) and drops blank Excel unnamed_* columns. Canonical ECM vs ECM+ values are not invented here.

Terms used on this page

  • CORE: The BigQuery layer where SQL turns raw source data into business meaning (for example enrollment episodes). CORE objects are views.
  • ECM: Enhanced Care Management: the Medi-Cal (CalAIM) benefit that pays Vayu to coordinate care for members with complex needs.
  • ECM+: Vayu's extra clinical services on top of ECM: billed visits with behavioral health (BH) clinicians or dietitian and diabetes educators (RDCDCES).
  • Sprite: Sprite Health, Vayu's EHR and care management system. Monthly reports are exported from it.
  • STG: Staging: the BigQuery layer that holds source files as they arrived, with light cleanup only.
