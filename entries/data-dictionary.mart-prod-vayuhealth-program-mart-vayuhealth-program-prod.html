Mart / Prod (VayuHealth_Program_MART, VayuHealth_Program_PROD)

Object Mart / Prod (VayuHealth_Program_MART, VayuHealth_Program_PROD)

Business definition

MART_Cumulative_Members is the persistent member book (“Cumulative” lives here). Historical seed through 2026-08-31 is complete (MIG_Tableau_Cumulative_Members / cleaned base). Do not reseed or delete historical rows. Monthly applies MERGE this month's Incoming into that table: update matching keys, insert new enrollments, never delete rows that are only in the base. The book stores pipeline snake_case names. VW_Cumulative_Members publishes the seeded cumulative-file headers (workflowStatus, Pathway, Phase_1_Days, HbA1c_GMI_Baseline, and the rest of that file) so Tableau can keep those fields. Tableau must use this view, never MART_Cumulative_Members. A bare SELECT * from MART exposes snake_case names (workflow_status) and invalidates the workbook; the SQL apply asserts the published names after every run. BigQuery treats column names as case-insensitive, so snake_case aliases such as pathway are not published next to Pathway. Columns that are not on the file, including clinical markers and device flags used by the phase and pathway calculations, are still on the view under their stored names. region on that view is grouped: Humboldt and Sierra become Humboldt; Shasta, Tehama, and Trinity are each one title-case label.

On MATCH, baselines, Phase 1–4 dates/days, and care_coordinator_team are fill-blank only. For Enrolled rows with a start date, Incoming may NULL discontinuation_date / ecm_enrollment_end_date when that date is strictly before the start (stale other-program exit); MERGE accepts the clear. Non-enrolled rows keep fill-blank on those exit dates. discontinuation_reason and discontinuation_reason_code come from the MIF tab and replace the stored value only when MIF has a value (also cleared when the Enrolled stale-disc rule nulls the date). Six-month / most-recent A1c and assessment most-recent overwrite only when Incoming has a value. Pathway, workflow status, and other non-locked fields still refresh from CORE. pof is the Demographics column. dm_type / direct_referral are computed on Incoming from tags. A confirmed enrollment requires a start date and care team Sequoia, Redwoods, Mariposa, or Sundial. Rows already on MART that fail that test are not deleted; they drop out of the monthly update until the stored team is an official team.

MART_Monthly_Members_Serviced is one row per member_cin + reporting_month. Purpose: the program member-month book — every member whose enrollment episode overlapped the reporting month (still enrolled or discontinued during the month), whether or not they had documented ECM/ECM+ service that month. Spine = ECM/ECM+ event members for the month union members with an overlapping enrollment episode on MART_Cumulative_Members (active_during_month = 1). Service fields come from MART_Monthly_ECM_ECMPlus_Events; ecm_category = No service means no ECM and no ECM+ that month (missed opportunity on the roster), including members discontinued in-month. Coalesce order (first non-null wins per field): (1) MART_Cumulative_Members with flexible name matching — episode preference exact ecm_enrollment_start_date → overlapping episode in the reporting month → latest cumulative row for that CIN; (2) CORE_ECMPlus_Member_Demos; (3) CORE_ECM_Tracker_Members. pathway comes only from that cumulative episode (ECM+ and Tracker pathway values are not used). pof and discontinuation_reason_code come from the cumulative book only. Blank pathway is not enrolled, including Exclude. Key service fields: ecm_category (ECM only / ECM+ only / ECM and ECM+ / No service), ecm_valid_activity_count, ecm_billed_touch_count, bh_count, rd_count, bh_or_rd_count, both_bh_and_rd_flag, no_service_in_the_month. Active membership flags: active_during_month, active_at_month_end, new_enrollment_in_month, discontinued_in_month (discontinued_in_month = end date and/or discontinuation date falls in the reporting month; see docs/metric_definitions.md).

Terms used on this page

  • A1c: A blood test that shows a person's average blood sugar over about the last three months. Also written HbA1c. Higher numbers mean less controlled diabetes.
  • BigQuery: Google's cloud database where the pipeline stores its tables.
  • CIN: Client Index Number: the Medi-Cal member ID. It is PHI. Never type a real one into GitHub.
  • CORE: The BigQuery layer where SQL turns raw source data into business meaning (for example enrollment episodes). CORE objects are views.
  • ECM: Enhanced Care Management: the Medi-Cal (CalAIM) benefit that pays Vayu to coordinate care for members with complex needs.
  • ECM+: Vayu's extra clinical services on top of ECM: billed visits with behavioral health (BH) clinicians or dietitian and diabetes educators (RDCDCES).
  • MART: The BigQuery layer of analysis-ready tables, such as one row per member or per member per month.
  • MERGE: A database step that updates rows that already exist and adds rows that are new, without duplicating them.
  • MIF: Member Information File: the ECM file shared with the health plan. It holds discontinuation reasons and population-of-focus flags.
  • Pathway: How a member's diabetes is tracked: CGM, BGM, or A1c. Based on their devices and recent readings.
  • Tableau: The dashboard tool Vayu uses for program reporting.
