Data Dictionary / ECM and ECM+ services

STG_ECMPlus_Encounters

Object Staging (VayuHealth_Program_STG) · STG_ECMPlus_Encounters

Business definition

ECM+ encounters CSV only. Required: member_cin, encounter_date. Optional but preferred: encounter_id (unique per encounter). Monthly extracts may include other encounter_date months; the loader replaces only the current reporting_month slice, then skips rows whose encounter_id already exists elsewhere in STG (composite identity fallback if encounter_id is blank). Precomputed BH/RD / is_duplicate_row columns from the extract are dropped so SQL owns BH/RD. Sprite claim-line columns (claim_amount, claim_status, claim_service_code) are dropped on load — those fan one encounter into many CSV rows; claim itemization stays in a separate script. The loader then collapses to one STG row per encounter_id so CORE / MART / PROD stay at encounter grain. Optional Sprite demo fields (gender, city, zip, etc.) are kept when present for PROD demo coalesce.

Terms used on this page

  • BH: Behavioral health: mental health services such as therapy or counseling.
  • CORE: The BigQuery layer where SQL turns raw source data into business meaning (for example enrollment episodes). CORE objects are views.
  • ECM: Enhanced Care Management: the Medi-Cal (CalAIM) benefit that pays Vayu to coordinate care for members with complex needs.
  • ECM+: Vayu's extra clinical services on top of ECM: billed visits with behavioral health (BH) clinicians or dietitian and diabetes educators (RDCDCES).
  • MART: The BigQuery layer of analysis-ready tables, such as one row per member or per member per month.
  • PROD: The BigQuery layer of approved views. Tableau and Connected Sheets connect only to PROD.
  • Sprite: Sprite Health, Vayu's EHR and care management system. Monthly reports are exported from it.
  • STG: Staging: the BigQuery layer that holds source files as they arrived, with light cleanup only.
