Business definition

One row per logical batch, not per physical input file.

The Stanislaus load pairs the Cozeva Demographics file and the HbA1c file in one pass and snapshots them with the same pipeline_run_id. That run id plus county is the pair. Receipt month is not the pair key, so two batches in one month are not merged, and a blank run id is not treated as a match. If more than one HbA1c filename shares the run id, the batch stays unpaired (enrichment_pair_ambiguous).

Shasta and Humboldt were checked. Each loader reads one A1c file and does not attach a second file, so this pairing rule is not applied to them.

membership_file_name is the physical file whose distinct CIN count is total_members_received for that month. For Stanislaus that is the Cozeva Demographics file, before age and A1c filters. Members on that file with no HbA1c row stay in the count. HbA1c-only CINs are hba1c_only_member_count and are not in the denominator. Duplicate HbA1c rows for one CIN are collapsed before the join.

enrichment_file_name keeps the paired HbA1c filename. receipt_month is the membership file's sourcing month.

Sheet sync has no file id. Verified eligible and program exclusions attach to the Cozeva Demographics CIN on that batch, using that file's receipt month.
